Pseudo-elements

A pseudo-element styles a part of an element — a part you never wrote. The browser builds it, and it vanishes the moment the rule goes away. Two colons: :: is a part, : is a state.

1 — Parts of text you already have

The first letter of this paragraph is twice the size, and the first line is set in small caps — both without touching the HTML.

A second paragraph gets the same treatment, because the rules are not tied to a class.

2 — ::before and ::after: content you never wrote

Both of them need content. Without it the rule is silent — the pseudo-element is never generated, and it takes up no room at all. Note that the string "\00BB " carries two spaces: the first one ends the \00BB escape sequence, so only the second one reaches the page.

This line starts with a mark that exists only in the CSS.

So does the line before it, and every other note on this page — one rule, every element carrying the class.

The page title has one too: h1::after { content: " \2713"; color: #2E9E5B; }

.note::before { content: "\00BB "; color: #1e4fa8; font-weight: bold; } — the same rule is drawing the chevron at the start of every grey note on this page.

3 — Putting a picture in, three ways

The three pictures below are the files star.svg, check.png and underline.svg, sitting next to this page — and there is no <img> element anywhere in this document. All three are placed by the stylesheet.

Starred heading — the picture is one declaration away

A shorter one

.star::after { content: url("star.svg"); } — the picture is the value of the property, so it obeys the rules of inline content: it sits on the text baseline, the 24 × 24 SVG brings its own size, and the heading's line box grows to make room for it.

  • content: "" generates an empty box that you are allowed to size.
  • background-image puts the picture inside that box.
  • background-size decides how big the picture is drawn.

.checks { list-style: none; margin: 0; padding: 0; } — the built-in bullet is switched off first, so the tick is the only mark left.

.checks li::before { content: ""; display: inline-block; width: 18px; height: 18px; margin-right: 8px; vertical-align: -4px; background: url("check.png") center / contain no-repeat; }

The word highlighted wears a second SVG underneath it — a marker stroke that stretches to whatever width the word turns out to be.

.hl { position: relative; }

.hl::after { content: ""; position: absolute; left: 0; right: 0; bottom: -5px; height: 7px; background: url("underline.svg") no-repeat; background-size: 100% 100%; } — zero pixels of HTML were added around that word.

4 — Content that comes from the HTML

The value does not have to be a string you typed into the CSS. attr() reads it out of an attribute instead — which is how tooltips and badges were built long before anybody reached for JavaScript.

hover me this one is pinned

.tag::after { content: attr(data-hint); position: absolute; left: 0; top: 100%; opacity: 0; } — content reads the attribute and opacity hides it; everything else in that block is paint, placement and spacing.

.tag:hover::after, .tag.pinned::after { opacity: 1; } — a pseudo-class switching a pseudo-element on, with the wording left in the markup where somebody can edit it.

5 — Not every mark needs a picture

A shape you can draw with borders is a shape you do not have to download. The tail under this box is four transparent borders with only the top one coloured.

This box is an ordinary paragraph. The tail below it is an ::after with nothing in it but borders.

.bubble::after { content: ""; position: absolute; left: 30px; top: 100%; border: 8px solid transparent; border-top-color: #0e3f8c; }

6 — What they cannot do

  • No content, no pseudo-element. The rule parses, looks harmless, and does nothing at all — the quietest failure in this whole chapter.
  • One of each, per element. An element can have a ::before and an ::after, and no more.
  • Not in the DOM. querySelector cannot find them, selecting the text does not copy them, and you cannot nest one inside another.
  • Decorative by default. Screen readers do not reliably announce generated text, and content: url() carries no text alternative. If a picture carries meaning, write a real <img> with a real alt.
