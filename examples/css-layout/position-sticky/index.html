position: sticky

sticky is relative until the box reaches the offset you gave it, and fixed from then on — but only for as long as its own container is on screen. No offset, no sticking.

1 · On the page it sticks to the window

sticky section heading

Scroll the page. This heading holds its place at the top of the window while the rest of its section is read — the pattern behind section titles, table headers and alphabetical lists.

It is still relative to its container: the moment the bottom of this section goes past, the heading leaves with it. It cannot escape upwards the way a fixed box would.

Watch the heading stay put for a while, and then walk off the top together with the last line of this section.

Nothing here is a special case. The scrolling container is the page, so the offset is measured from the top of the window, and the thing that releases the heading is this section element.

If two sticky boxes overlap, the one later in the document wins — they do not queue up in a column the way you might hope.

3 · The fine print

rulewhy
an offset is requiredno top → the element never sticks
it needs a scrolling containerthe nearest scrollable ancestor is what it sticks to
it stays inside that containerit is released when the container scrolls past
give it a backgroundthe content scrolls underneath, not behind nothing

4 · When to reach for it

Sticky is the right tool when an element should be visible some of the time: a heading while its own section is on screen, a table header while the table is, a filter bar while the list is. Once the container has gone there is nothing left to stick to, and the element politely leaves.

That is the difference from fixed in one sentence: fixed is always there and never comes back; sticky is there exactly as long as its container is.

Sticky also needs an ancestor with some height to travel through. If the parent is only as tall as the sticky element itself there is no distance to travel, and it will look as though nothing happened — a very common surprise with a one-line parent.

And it does nothing if any ancestor hides the overflow along the sticky axis: overflow: hidden on the way up turns the sticky box into an ordinary one, silently, with no warning and nothing in DevTools to explain it.

The offset can be negative, and it can be on more than one axis: a heading with top: -1px is a common trick to stop a one-pixel seam showing above the pinned element while it scrolls.

Sticky is also not animated and not scripted — the browser decides when to pin, from the scroll position and the box's own geometry. You never move it yourself.
