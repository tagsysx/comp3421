SVG Loaders

Every spinner on this page is a path, a dash pattern, and one number that moves the pattern along it. No images, no libraries — and the first three need no script at all.

1 · The sliding line

One straight line. The pale run is the path itself; the blue pillar is the ink painted on it. Give the stroke a dash pattern of "28 80" and only one dash can ever be on the line at a time: 28 units of ink, then 80 of gap. Then animate a single number, stroke-dashoffset — the line is 100 units and the ink is 28, so travelling to -72 carries the ink exactly from the left end to the right, and back to 0 returns it. That is the whole loader.

The four sections after this one take it apart properly: where the dash comes from, what every frame actually looks like, why it reads as a bounce, and the six lines of CSS that do all of it.

pathLength="100" is what makes the numbers readable: it tells the browser to treat this line as 100 units long, so the dash values are percentages and the same three lines work on a line of any length. The easing is ease-in-out, which slows the ink as it reaches each end — that is what makes the turn read as a bounce rather than a jump.

Try this: change 28 to 60 and the ink becomes a fat comet — then change the travel to -40 as well, so that it still lands on the right end (line length minus ink length is what decides the travel). Delete the 50% step and the ink runs one way and snaps back. Swap ease-in-out for linear and the bounce turns mechanical.

Example 1, in detail

1b · Where the dash comes from

Only three things are doing work here. It is worth naming them before we take the animation apart, because every other loader on this page is built from the same three.

  • The path — the <line> we drew, carrying pathLength="100". This attribute does not move, resize or rescale anything. All it does is declare how long the line should be considered to be — 100 units — so that every dash number below is measured against that instead of against pixels. Note what it does not touch: stroke-width is still in ordinary SVG units, so the round cap stays the same size no matter what you put in pathLength.
  • The pattern — stroke-dasharray: 28 80. Not "one dash". A rhythm: 28 units of ink, then 80 units of gap, then the same again, for as long as the path lasts.
  • The mover — stroke-dashoffset. It shifts where that rhythm begins. Nothing is redrawn and the line does not move; the pattern slides along a path that stays exactly where it is.

The pattern is the part that catches people out, so let us put it on a line three times as long and look at it properly. Same two numbers, same pathLength trick — only the length of the line has changed:

Now cut the line back to the 100 units our loader actually uses, and only the first dash survives. The line is 100 units long and one period is 108, so the second dash would not begin until 108 — eight units past the end. One dash, one gap, and nothing to wrap around.

That "nothing to wrap around" is not decoration, it is the fix for a real bug. The first version of this loader used 28 72, whose period is exactly 100 — precisely the length of the line. Set the two side by side on the long line and the problem is obvious:

Why does landing on the mark matter? Because a dash that ends exactly at the start of the line still gets its round cap, and a cap is a semicircle of ink centred on that point — half of which falls inside the line. So on every bounce the ink reaches the right end and a small blob of ink flashes at the left end at the same moment. Making the gap bigger than the remaining length removes the collision entirely: the nearest other dash now lives at −36 to −8 units, well outside the path, so there is nothing there to paint a cap.

The rule to take away: keep ink + gap greater than the length of the path, and exactly one dash will ever be visible. Let it come out equal, or smaller, and the pattern tiles across the path and you will see more than one.

1c · Frame by frame

The bounce lasts 1.8 seconds. Below it is frozen nine times — every eighth of the cycle — so you can read the position off the page instead of trusting your eye.

Each row is the real animation, not a drawing of it: the same @keyframes rule, held still with animation-play-state: paused and a negative animation-delay that seeks to that phase. The two right-hand columns are read out of the browser.

Three things worth noticing. The highlighted row is the turning point at 0.900 s, where the offset reaches its full −72 and the ink sits on the right end covering units 72 to 100. The journey is mirror-symmetric — 0.225 s and 1.575 s are identical, and so are 0.450 s and 1.350 s — because the second half of the animation just runs the first half backwards. And the last row is the same state as the first, which is what makes the loop invisible.

One caveat, since these frames are held still by a fixed delay: if you change the duration in the box above, the delays stay where they are and the frames will no longer line up.

1d · Why the bounce reads as a bounce

The ink does not travel at a constant speed, and that is entirely down to ease-in-out. A CSS timing function is a cubic Bézier — honestly, it is one — so this curve is not an impression of the easing, it is the easing:

Swap ease-in-out for linear and every bar grows to the same height — the ink then moves like a metronome, and the same loader stops looking alive. That is the entire trick: a constant amount of motion spread unevenly across time is what our eyes read as weight.

1e · The code, line by line

Everything described above comes down to six lines. Nothing in them is a library or a special SVG feature — it is a stroke, a pattern, and a keyframes rule:

.wide .ink { stroke-width: 16; stroke-dasharray: 28 80; animation: slide 1.8s ease-in-out infinite; } @keyframes slide { 0%, 100% { stroke-dashoffset: 0; } 50% { stroke-dashoffset: -72; } }
  • stroke-width: 16 — how thick the ink is This also sets the round cap, because a cap is a semicircle of radius 16 / 2. That is why the ink looks a shade longer than its 28 units at each end, and why the cap could reach back onto the line in the version we had to fix.
  • stroke-dasharray: 28 80 — the rhythm Read it as a list of lengths, alternating ink and gap. Two numbers is all it takes: the browser repeats the pair for as long as the path runs.
  • animation: slide 1.8s ease-in-out infinite — the schedule Four words, four answers: which keyframes, how long one cycle lasts, how the speed varies inside it, and never stop.
  • 0%, 100% sharing one value — the seam Two selectors, one declaration. The state at the end of the cycle is the state at the start, so restarting is invisible. Delete either selector and you get a visible jump.
  • stroke-dashoffset: -72 — the far end The 72 is not a taste decision: it is 100 − 28, the line length minus the ink length. That is the distance that parks the ink on the right end. Any other number leaves it stranded somewhere in the middle.

One last thing, and it is the difference between this loader and the marching-ants trick in the dashed-strokes example. That one slides the offset by exactly one period, so the crawl continues smoothly and never stops. This one does not slide at all — it swings a single offset value between two fixed endpoints, and relies on the arms sharing a value to close the loop. Both are the same property of stroke-dashoffset, used in opposite directions: one for endless travel, one for a bounce that returns.

The rule under all four. stroke-dasharray says how long the ink is and how long the gap is; stroke-dashoffset says where along the path that pattern starts. Animate either one — or both — and a still drawing becomes a loader. Keep one number in mind: a dash plus its gap is one period. Slide the offset by a whole period and the dashes flow with no seam; slide it by less and the ink simply stops somewhere along the line.
