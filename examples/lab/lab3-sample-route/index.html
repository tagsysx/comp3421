A dot riding a path

A delivery route: the line draws itself, then a dot runs along the very same curve. No JavaScript, and no maths — the browser can follow a path for you.

Half one — the line draws itself

This is the same trick as the sliding bar in the lab: a dash pattern plus a moving offset. The difference is the scale. On a loading bar the pattern repeats many times along the line, so the offset travels one cycle. Here the dash is as long as the whole route, so the offset travels the route and the line appears to draw itself:

.route {
  stroke-dasharray: 100 100;          /* one dash the length of the route */
  animation: trace 3.4s ease-in-out infinite;
}

@keyframes trace {
  0%       { stroke-dashoffset: 100; }   /* nothing drawn yet        */
  55%, 90% { stroke-dashoffset: 0;   }   /* finished — and it waits  */
  100%     { stroke-dashoffset: 100; }   /* retreated                */
}

pathLength="100" is doing quiet work here. It tells the browser to treat the path as if it were 100 units long whatever its real length, so 100 and 0 mean "all of it" and "none of it" without anyone measuring a Bézier curve. The two stops at 55%, 90% are what hold the finished route still for a beat instead of snatching it away immediately.

Half two — the dot follows the same curve

offset-path puts an element on a curve; offset-distance says how far along it has got, as a percentage. The catch is that CSS cannot read your SVG, so the path data has to be written out a second time — copied from the d attribute:

.runner {
  offset-path: path("M18 116 C 56 116, 60 52, 100 52 S 148 116, 190 116 S 214 34, 232 26");
  offset-distance: 0%;
  animation: run 3.4s ease-in-out infinite;
}

Then give it the same stops and the same duration as the line. That shared duration is the whole choreography: change one and not the other and the dot arrives early or late. Stops of 55%, 90% also keep the dot parked at the end while the line is held.

The same route at 6 s instead of 3.4 s — slower, and easier to watch.

Try these

  1. Delete the offset-path line and watch the dot. It parks in the top-left corner — the single most common way this exercise goes wrong.
  2. Change only the dot's duration to 1.7s, leaving the line at 3.4s. The dot now makes two trips per drawing. That is the clearest possible demonstration of why the two must agree.
  3. Change ease-in-out to linear. A parcel does not accelerate, so linear is arguably more honest here — decide which you prefer.
  4. Change the stops from 55%, 90% to 55%, 55%. The hold disappears and the drawing retreats the instant it completes.
  5. Edit the path data in both places — the d attribute and offset-path — and watch both halves follow the new curve. Miss one and they part company.
