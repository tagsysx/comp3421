An icon that morphs on hover

A menu button becomes a close button, and nothing on this page runs on a clock. The shape answers your pointer: the shape is the state.

Move the pointer onto the icon

Both states, without a clock

Each line writes down only the state it moves to. The resting state stays on the line itself, and transition tweens the difference whenever the two no longer agree:

.icon line {
  transition: transform .45s cubic-bezier(.2, .8, .2, 1), opacity .3s linear;
}

.icon:hover .top { transform: translateY(18px) rotate(45deg); }
.icon:hover .mid { opacity: 0; }                    /* … it just hides      */
.icon:hover .bot { transform: translateY(-18px) rotate(-45deg); }

Nothing here draws a cross. The top line slides down by 18 — exactly its distance to the middle — and tilts one way; the bottom line slides up by 18 and tilts the other way; the middle line fades. Two lines crossing at the centre are a cross.

The line that must not be missing

An SVG shape does not turn about its own centre by default — it swings around the corner of the canvas, which for a line halfway down the viewBox looks like it is being flung off the card. One declaration fixes it:

.icon line { transform-origin: 60px 60px; }

Read that as "turn about the point (60, 60) of the SVG". All three lines name the same point, and that shared pivot is the whole reason they meet in the middle.

Note where that rule sits: on the lines, not on the wrapping <g>. It is tempting to write it once on the group — but transform-origin is not inherited, and it only affects the element that actually carries a transform. The <g> never transforms, so an origin on it does nothing and the lines silently keep the default 0 0. Naming the pivot on the things that move is the rule.

Same effect, staggered

The second icon has the same markup and the same hover rules. The only addition is a transition-delay per line, so the three move one after another instead of at once — a sequence built with no @keyframes at all:

Now imagine the same trick on your own shape

.icon.seq .mid { transition-delay: .12s; }
.icon.seq .bot { transition-delay: .24s; }

Try these

  1. Change 45deg to 30deg on both lines and hover again. The lines no longer meet — which tells you exactly where the 45 comes from.
  2. Delete the .mid hover rule. The middle bar stays put and the icon turns into a mess. That is the one line of the three that is allowed to do the least.
  3. Move the transform-origin rule off .icon line and onto .icon g instead, then hover. This is the mistake the rule exists to prevent, and it is a subtle one: nothing errors, the property is simply ignored.
  4. Change the cubic-bezier to linear, then to cubic-bezier(.9, 0, 1, .4). Slide and fade want different easings; a slide usually wants to start quickly.
  5. Add transition-delay: .3s to .top as well as the others. The whole thing now waits before it moves, and the delay is what makes it feel deliberate rather than twitchy.
  6. Make the two durations equal — transform .45s, opacity .45s. The middle line now lingers while the other two have already crossed, and the cross looks unfinished for a moment. Different durations are a decision, not a default.
